# Hierarchical drill-down — phase one

This phase deliberately keeps the product focused on direct data exploration. Hierarchy is an optional visualization capability, not a new analytics platform.

## Standard parent-child structure

The reusable structure is an adjacency list. Only two relationship columns are required:

| Column | Requirement | Meaning |
|---|---|---|
| `node_id` | Required | Unique identifier for a hierarchy member |
| `parent_node_id` | Required | Identifier of the parent; blank only for a root |
| `node_label` | Recommended | Business-facing member label |
| `hierarchy_level` | Recommended | Numeric level beginning at 1 |
| `level_name` | Recommended | Business name such as LOB, Region, Market, Cost Center, or Product |
| `hierarchy_name` | Optional | Supports more than one hierarchy in a file |
| `period_date` | Optional | Reporting date when node measures vary over time |
| `actual_value` | Optional | Actual measure attached to the node-period |
| `plan_value` | Optional | Budget, plan, or target attached to the node-period |

Example:

```csv
hierarchy_name,node_id,parent_node_id,node_label,hierarchy_level,level_name,period_date,actual_value,plan_value
Enterprise LOB,ENT,,Enterprise,1,Enterprise,2026-01-31,1250000,1300000
Enterprise LOB,LOB-WIRELESS,ENT,Wireless,2,LOB,2026-01-31,760000,790000
Enterprise LOB,REGION-WEST,LOB-WIRELESS,West,3,Region,2026-01-31,290000,310000
Enterprise LOB,MARKET-LA,REGION-WEST,Los Angeles,4,Market,2026-01-31,135000,150000
```

The hierarchy may contain two levels or more than ten levels. The application does not require a fixed depth.

When `node_id` and `parent_node_id` are absent and no mapping is supplied, the hierarchy visualization is simply not enabled. The regular dimensional exploration remains available.

## Live public demonstration hierarchy

The City of Los Angeles procurement source does not publish one official ten-level organizational hierarchy. The demo therefore creates a clearly labeled analytical hierarchy using two virtual roots plus eight live source fields:

1. Enterprise — City of Los Angeles
2. Line of Business — Procurement Payments
3. Department
4. Government Activity
5. Fund Group
6. Fund Type
7. Fund
8. Account
9. Expenditure Type
10. Vendor

The first two levels are generated by the adapter. Levels three through ten are queried on demand from the live multi-million-row source. Every node receives a generated `node_id` and `parent_node_id`, payment total, transaction count, and share of its parent.

The org chart renders only the selected path and its immediate children. This preserves readability while allowing a user to move through all ten levels.

## Phase-one user flow

1. Prepare or identify the hierarchy relationship.
2. Confirm `node_id` and `parent_node_id`.
3. Load the root.
4. Select a child node.
5. Query and display that node's children.
6. Continue until the leaf level.
7. Use breadcrumbs or the level rail to move back up.

## Next phase

The next hierarchy phase can add a visual mapper for uploaded files where the user orders separate level columns such as:

```text
Enterprise → LOB → Region → Market → Cost Center → Product
```

The mapper would convert those level columns into the same adjacency-list contract internally. That is intentionally separate from this first implementation so the primary drill experience stays simple.
